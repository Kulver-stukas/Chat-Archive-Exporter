# Writer claim recovery hotfix — Issue #6

A previous browser/worker can leave an empty `writer-*.lock` file in `ChatGPT/.chat-archive/writers/`, blocking all workspaces even when Vault permissions are granted. The hotfix retains the global cooperative guard because the global mutable index remains shared. Each new marker identifies an installation, operation, workspace, optional job and resources. The stable local installation ID persists over normal upgrades. Under the browser-local exclusive Web Lock, an installation automatically removes its own abandoned markers, even if marker JSON was never written. Queues, pending source records, settings and archived files remain untouched and normal integrity checks still apply.

Tools → Diagnostics → Review writer claims lists ownership, workspace relation, operation and age. Stop all other browser/extension instances that write to the Vault, review the snapshot, tick the confirmation and click Clear reviewed locks. The current local Web Lock must be available and the snapshot unchanged. No foreign or legacy marker is automatically stolen by time. Old anonymous claims cannot be attributed retrospectively. An older browser without the guard does not participate; do not run it concurrently. Do not clone an installation's local storage to a second simultaneous writer. Shared local filesystem visibility is assumed; no distributed/cloud-replica guarantee. No heartbeat or age-based lease is used as proof of death.

No new permissions, archive migration or provider. Issue #7 tracks provider/workspace-scoped authoritative indexes, derived global inventory and actual resource-level coordination for rev.4. The enable-monitoring access probe is outside the writer transaction; full network/disk separation is deferred. Manifest version 0.2.0.4 distinguishes this unpacked preview from 0.2.0.3; architecture revision remains rev.3.
