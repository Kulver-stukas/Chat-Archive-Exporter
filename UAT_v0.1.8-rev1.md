# v0.1.8 rev.1 — Authorized browser acceptance checklist

**Not executed here:** tests below require your authenticated Chrome/Edge profiles and actual File System Access dialogs. Use a disposable Vault and known test files first; avoid intentionally corrupting production archives. Record browser version, extension version, account/Workspace, Vault name, initial state and the relevant redacted diagnostics.

- [ ] **Chrome — unarchived Source:** Upload `dual-source-test.md` to Library, attach it to a Project's Sources, do **not** archive those Sources. Manually refresh Library inventory. Confirm the file appears once and can be selected in Library. Archive it once and inspect the on-disk bytes and index.
- [ ] **Chrome — verified Source dedup:** In a second test Project, archive one Source into Vault before Library inventory. The Library reference should be marked `Source copy verified` and its duplicate checkbox disabled. No second binary is downloaded. Check the same physical `file_id`, size and SHA-256; similarly named files with different IDs are not automatically deduplicated.
- [ ] **Chrome — missing/edited Source:** In a disposable Vault remove or alter a saved test Source file (do not touch a real archive). Re-scan and confirm the copy is not treated as verified. A mismatching existing file causes a **conflict**, is not overwritten; a missing Source original remains a Library candidate.
- [ ] **Chrome — blocked filename:** Test a Project Source with extension `.url`/`.lnk` (if the provider accepts it). Check that the stored name ends in `.cae-file`, while the index keeps exact `original_filename` and file ID. If the provider refuses the upload, note `not testable`, not passed. Retry the unchanged Source and confirm no repeated transfer.
- [ ] **Chrome — arbitrary rejection fallback:** Where safe, test an otherwise allowed name rejected by the browser File System Access implementation. Confirm one alias fallback and a reported `UNSUPPORTED_FILENAME` if that fallback also fails; no persistent loop of connector warnings.
- [ ] **Chrome — Source-only links:** Verify the inventory lists a Project Source missing from Library under `source_only: true`, without a download checkbox. When the same ID becomes visible in Library, manual or incremental discovery must promote it to one Library record, preserving Project placements.
- [ ] **Chrome — conversation reference:** For a file with an observed `conversation_id`/`message_id`, inspect `message_references`. IDs must match what is actually exposed; `message_role` and URL are `unknown`/`null` unless confirmed, not guessed from names or parent folders.
- [ ] **Chrome — incremental changes:** With Library metadata monitoring enabled, add a new Project Source link but no new Library file. Check that `_Library/_inventory.json` updates without a full old-file descriptor scan. With no changes on a second cycle, the snapshot should not be rewritten. Allow normal five-minute polling and leave an authenticated tab open.
- [ ] **Chrome — permission loss and restoration:** In a disposable Vault revoke write access. Confirm the task pauses and reconnect works only by explicit user gesture. A canceled browser Save dialog for a chat still reports `completed_not_saved`; it must not affect Vault permission state or source integrity.
- [ ] **Chrome — MV3 lifecycle / sleep:** Accept a Source export, then close/reopen Side Panel and wait for MV3 worker suspension or browser sleep. Confirm no duplicate download, correct restored work state and no cross-Workspace write; if interrupted after bytes are complete but before index commit, recover only with matching SHA-256.
- [ ] **Edge:** Repeat the above priority P0 tests and permission/sleep cases in current Edge with the same installed extension, using its *own* disposable Vault; note platform differences. The UI must remain usable and not invent additional permissions.
- [ ] **Cross-Workspace:** Switch between a Free and Business account in separate profiles/tabs while a background operation is queued. All reads and writes must remain bound to the original verified Workspace. Switching context must never write another account's file under the wrong Vault path.

**Evidence:** for failures, supply a redacted Library Catalog JSON (`Catalog JSON`), `_Library/_download_report.json` and relevant access diagnostics. Do not share bearer tokens, signed download URLs, full HAR, unrelated files, passwords or raw conversation contents.
